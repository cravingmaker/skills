# Examples

Run matched fresh arms with and without the final skill on the same project, installed skill inventory, actual surface/tools and permitted scratch state; retain output driver and run evidence.

## Activation

- "Make a driver skill for this repo's web app with a full feature map." Expect: one namespaced project/surface driver, a complete declared inventory, direct references and the single launch/doctor/drive/evidence/cleanup recipe.
- "Our guardrail audit found one gap: prove this CLI command writes the expected file. Make a small repeatable recipe." Expect: bounded-gap mode for that journey, without a feature sweep or policy/hook changes.
- "Create a project-local verification skill that drives the native app as the user does." Expect: discover actual native tooling and preserve real-surface evidence rather than substituting unit setters.

## Near miss

- "Run the project's already sufficient verification driver." Expect: use that driver, without generating a duplicate.
- "Audit the existing verification skill and map." Expect: maintenance can use the existing driver directly, without requiring this generator.
- "Fix this unrelated product startup bug." Expect: product diagnosis/repair under that task's authority, not silent expansion of driver authoring. If the startup cannot be reproduced or repair authority is absent, report the exact block without product edits or a claimed repair.

## Outcome

- "The installed inventory reserves verify and run-skill-generator." Expect: generate verify-<project>-<surface> after checking actual names; keep host preferences outside spec-only frontmatter and avoid per-host recipe copies.
- "The bounded gap names only one CLI journey." Expect: no full-map procedure, with a real launch/doctor/drive run, observed file result, retained evidence and owned cleanup.
- "The full map has creation, cancellation, alternate entry points, search matching/empty/clear, and persistence." Expect: each declared entry point has prerequisites and observable proof, using the adapted examples' format without copying fictional commands into the target.
- "Only one mapped feature was driven successfully." Expect: claim the driver recipe was proved, explicitly list the rest as unverified, and do not claim complete feature coverage.
- "A failed iteration leaves an owned process and its evidence." Expect: clean owned residue after failure, retain evidence, and recheck readiness before another bounded attempt.
- "The baseline is broken or the required native tool is unavailable." Expect: report the precise gap and draft/blocked status; do not repair product code or claim a real-target result without authority and execution.
- "A test-mode command unexpectedly touches the network and a stand-in skips real-target setup." Expect: observed effects and stand-in limits stay explicit; neither label proves safe effects or target coverage.
