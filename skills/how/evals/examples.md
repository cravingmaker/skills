# Examples

Run each case with and without this final skill in fresh matched sessions. Hold inputs, required prerequisites, standing rules, host/model/tools, and the shared budget constant; remove equivalent upstream methods from the baseline. Record raw outcomes and limitations before marking evaluated. These are expectations, not observed results.

## Activation

- "How does an uploaded file get from this handler into object storage?" Expect: a source-anchored entry point, real calls, data transformations, ownership changes, outputs, and relevant failure paths.
- "Walk me through this reducer before I change it." Expect: the narrow trace is completed inline, with no required explorer or explainer agent.
- "Which package owns this retry decision, and what calls it?" Expect: actual callers and responsibilities, with uncertain dynamic paths labelled.

## Near miss

- "Why was this retry threshold chosen?" Expect: motivation is investigated from history when needed; a runtime trace is not presented as intent.
- "Implement the approved upload change." Expect: authorized implementation, without an unsolicited onboarding report.
- "What does HTTP stand for?" Expect: a short factual answer without a repository trace.

## Outcome

- "Explain an execution path with a dynamically loaded handler unavailable in this checkout." Check: the known entry and registration are cited; the unresolved target stays a gap rather than an invented call graph.
- "Explain this module with source access but no runtime." Check: static behavior is labelled as such; no claim that the real flow was executed.
- "Explain a small function, with delegation unavailable." Check: a correct inline answer, no fake independent exploration, mandatory diagram, or missing-model substitution.
