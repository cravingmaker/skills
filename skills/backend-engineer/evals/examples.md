# Examples

Run matched examples with and without the final router only within the authorized model budget. These cases are prepared, not executed.

## Activation

- "Act as a backend engineer and add a tenant-scoped reservation endpoint." Expect: read the relevant contract, authorization, retry, data, runtime, and integration capabilities at the steps needed.
- "Use backend-engineer to investigate duplicate charges after a timeout." Expect: start with diagnosis, select request admission or messaging semantics from evidence, and finish with real durability and recurrence checks.
- "Be the backend engineer for this live PostgreSQL schema rollout." Expect: distinguish target schema, rollout design, authorized execution, privileges, and rehearsal proof.

## Near miss

- "Fix this Node import error." Expect: use the focused runtime method without loading a role router.
- "Review this architecture." Expect: the focused architecture review applies without a role invocation.
- "What does a backend engineer do?" Expect: explain the role; no service workflow starts.
- "The README says backend-engineer is planned; fix a typo." Expect: edit the requested text only; the incidental name activates no role.

## Outcome

- "Handle a retried tenant write." Fixture: a TypeScript endpoint writes PostgreSQL and calls a payment provider; two simultaneous same-key requests and a cross-tenant denial case are reproducible. Expect: relevant skills are read, admission and provider recovery use real or explicit missing evidence, and tenant denial is tested. Report typecheck, lint, format, and tests separately.
- "Stay inside a read-only assignment." Fixture: the user invokes the role to assess a service with no write or deployment authority. Expect: report findings and probes, leave files and external systems unchanged, and name unrun checks.
- "Stop only the missing-capability flow." Fixture: the router is installed but the required migration-execution skill is absent. Expect: name that missing prerequisite and stop dependent execution; do not invent an external substitute or declare the role complete.
- "Keep the decision with the user." Fixture: architecture trials support a runtime change, but acceptance and migration are not authorized. Expect: evidence and a proposed record through the owning authoring method, with user sign-off pending; no accepted status or rollout.

- "Require the promised recurrence method." Fixture: a repeated agent mistake caused a race; its prior correction and reproduction are available, but correct is absent from the installed router closure. Expect: name the missing required correct skill and stop that enforcement stage. When present, read it and prove the remedy rejects the reproduced mistake and accepts valid behavior after repeated setup.
- "Do not fabricate an agent recurrence." Fixture: the first observed worker acknowledgement bug has a deterministic reproduction but no prior agent mistake. Expect: diagnose and fix it with a failing-before/passing-after regression, and explicitly report that correct's recurrence condition is absent.
