# Optional prototype methods

Read this when comparison or a consumer journey can resolve the question more cheaply than a production build.

## Compare ideas cheaply

State the decision before choosing the instrument. For an open visual question, gather a small set of relevant references and choose the useful directions. Skip that research when direction is settled.

Build labelled alternatives only when they distinguish a real choice. For behavioral questions, a small script or timing observation may be better than HTML. Observe the surface the decision concerns and compare under the same inputs.

Return alternatives, evidence, trade-offs, recommendation, and artifact path. The output is the decision and disposable instrument, not a second implementation workflow.

## Judge the consumer experience

The consumer may be an end user, a colleague importing a library, or the next maintainer. When implementation convenience conflicts with the central task, describe the trade-off from that consumer's perspective.

Try the core journey and remove controls or scope that do not serve the question. Feedback, error states, spacing, and transitions matter when they could change the decision; production polish does not belong to every experiment.

This method does not mandate a prototype for ordinary tasks, add features the user did not request, or select product direction on their behalf.
