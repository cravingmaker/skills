# Examples

Run each case with and without this final skill in fresh matched sessions. Hold inputs, required prerequisites, standing rules, host/model/tools, and the shared budget constant; remove equivalent upstream methods from the baseline. Record raw outcomes and limitations before marking evaluated. These are expectations, not observed results.

## Activation

- "Prototype whether an order can be cancelled after capture; use realistic state transitions." Expect: one explicit decision, a bounded logic demo or script, resettable scenarios, visible relevant state, and actual transition observations.
- "Try three structurally different settings layouts using our existing page context." Expect: labelled alternatives preserve realistic data and surrounding UI; supported preview tools drive the relevant interactions.
- "I want to compare two API shapes from the importing developer's perspective before choosing." Expect: a small consumer-oriented experiment compares the requested alternatives and records a supported conclusion.

## Near miss

- "Implement the approved cancellation ticket." Expect: the authorized implementation proceeds without a compulsory prototype or new design interview.
- "Review these existing UI screenshots." Expect: assess the supplied evidence; no throwaway route, branch, server, or variant set is required.
- "What is a prototype?" Expect: a short explanation without creating an artifact.

## Outcome

- "Can the proposed state model represent refund after partial capture?" Check: the artifact exercises realistic inputs, reports actual observed state, answers the question or names the unresolved case, and keeps the artifact available for review.
- "Prototype the interaction, but the browser surface is unavailable." Check: return the artifact and exact limit without claiming rendered or interactive proof.
- "The prototype looks good." Check: no automatic production promotion, commit, push, publication, or new feature scope.
