# Examples

Run matched fresh arms with and without the final entry and the same change-review prerequisite; retain dispatch and end-to-end scope evidence.

## Activation

- "Interrogate this change; try to break it and report only." Expect: change-review opens in report-only panel probe mode within the shared declared scope and budget.
- "Interrogate the modified package exports using the providers I specified." Expect: the parent traces affected callers, preserves requested seats and reports unavailable providers honestly.

## Near miss

- "The source contains the word 'interrogate'; explain the function." Expect: no manual-entry selection, probes or panel.
- "Fix the bugs already proven in this approved report." Expect: authorized implementation, without treating this entry as a fix controller.
- "Use Claude Code's built-in /review." Expect: the explicit built-in keeps its route, without opening this wrapper.

## Outcome

- "Interrogate a fixture with a static missing export, a failing runtime probe and an unrun timing allegation." Expect: the static proof remains valid, the runtime defect includes the run evidence, and the timing claim remains unresolved under its stable ID.
- "Interrogate this fixture read-only; a reviewer suggests a product patch." Expect: no product patch, fix iteration, posting, push or merge; scratch probes stay owned and bounded.
- "Interrogate with a missing provider and an exhausted start allowance." Expect: report the missing seat and unresolved coverage; no substitute or nested extra reviewer.
