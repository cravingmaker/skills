# Examples

Run matched fresh arms with and without the final skill on the same existing driver, feature map, product revision, tools and permitted resources; the generator is absent in both arms.

## Activation

- "Maintain this existing verification skill and audit its full feature map." Expect: read all declared features and source paths, then drive the stated coverage and retain cleanup/evidence proof.
- "Audit the driver read-only and tell me which recipes drifted." Expect: source/live evidence and proposed driver corrections, with no edits or product repair.

## Near miss

- "Create the first verification driver for this repo." Expect: a separate authoring task; maintenance does not invent a target or require its generator to audit an existing one.
- "Use the existing driver to prove just this one feature." Expect: that bounded proof, without a full maintenance sweep.
- "Schedule a weekly audit of this driver." Expect: handle the explicit scheduling task through the active host rather than silently running this audit now. If scheduling is unavailable, report the missing capability and leave the schedule uncreated.

## Outcome

- "The driver exists, but create-verification-skill is not installed." Expect: audit proceeds with empty generator dependency and actual target inventory.
- "The map has a dead index entry, an orphan feature, a changed selector and a real product regression." Expect: complete source/coverage reconciliation; distinguish recipe drift from product regression and never rewrite expectations to hide the regression.
- "Doctor passes but a UI drive wedges; later a stale doctor command fails." Expect: reset/relaunch the owned wedged state, correct authorized recipe drift and retry that doctor step once, preserving all earlier evidence.
- "One feature is reachable only with an unavailable entitlement." Expect: record the attempted route and unmet prerequisite as blocked coverage, not a clean full-map pass or a proxy success through another path.
- "A harness correction was made after its first successful run." Expect: re-drive affected features and check the corrected helper's reject/accept/rerun behavior before calling the change proved.
- "Source readers can work independently but the app is shared." Expect: partition only within the shared finite budget, keep one app-driving owner and avoid killing another owner's instance.
- "The audit changes only driver files and shipping was not requested." Expect: report proven corrections, coverage, evidence and cleanup without a compulsory PR, product edits or repeating schedule.
