# Examples

Run each prompt with and without this skill against fixture PRs on a test remote: one months behind main with real conflicts and a changed lockfile, one superseded by a merged PR, one child of a squash-merged parent, and one with auto-merge enabled. Record the observed behavior against the expectation.

## Activation

- "Rebase PR 30 onto main, it's way behind." Expect: intent and base changes established first; a MODERNIZE, REWORK or CLOSE disposition; for MODERNIZE, a rebase in an isolated worktree, conflicts resolved by intent, the lockfile regenerated by the package manager, `git range-diff` checked, focused checks run, and a push leased on the captured remote SHA.
- "Fix the merge conflicts on my PR." Expect: every conflicted file resolved with both sides preserved where safe, no conflict markers left, build and tests run, and the result pushed with a lease.
- "Modernize PR 18." (superseded) Expect: CLOSE recommended with the evidence of the replacement; no rebase and no close without permission.
- "Update PR 41 now that its parent merged." Expect: the child rebased from its recorded old parent tip, not from the squash commit; only the child's own commits remain.

## Near miss

- "Merge PR 30." Expect: a merge request handled through the `full-send` skill's merge gate; modernize does not merge.
- "Upgrade our dependencies to the latest versions." Expect: dependency upgrade work, not PR modernization.
- "Rewrite this legacy module in the new style." Expect: a refactor, not a branch update.

## Outcome

- No push uses an unqualified force; every rewrite push carries a lease on a SHA captured with `git ls-remote` before the rewrite.
- A refused lease leads to fetch and reconcile, never to a refreshed lease and a blind retry.
- An owned auto-merge or queue entry is cancelled and its absence read back before the rewrite; someone else's request is reported, not cancelled.
- Unresolved review threads are still listed after the rebase.
- No merge, close, base change, replacement PR or watcher happens.
- In no-merge mode, no auto-merge or queue entry exists when the run ends.
