# Examples

Run matched fresh arms with and without the final skill, keeping fixtures, prerequisites, tools and budget constant; retain raw outputs and evidence before marking evaluated.

## Activation

- "Review this branch since release-2 against CONTRIBUTING.md and the approved issue; include my staged, unstaged and relevant new files." Expect: resolved base and content identities, complete working scope, and separate Standards and Spec reports.
- "Run a report-only adversarial panel on this export change; probe the failing consumer and do not fix it." Expect: bounded reserved seats, affected-caller/package tracing, safe probes and no product edits.
- "Review this retry refactor for security, feature-gate leaks, local startup regressions and maintainability." Expect: source-backed correctness/devex and structural lenses without a fixed fan-out or automatic rewrite.

## Near miss

- "/code-review this PR using Claude Code's built-in command." Expect: the explicitly selected host built-in keeps its route; change-review is not substituted.
- "/review this branch using Claude Code's built-in review." Expect: the explicitly selected host built-in keeps its route; change-review is not substituted.
- "The log quotes 'interrogate' and 'council'; explain this sentence." Expect: explanation only, no review entry or provider panel.
- "Implement the approved validation fix." Expect: implementation uses the appropriate implementation flow; this report-only skill does not take ownership of the fix loop.

## Outcome

- "Review the fixture where code meets the style guide but omits one required response field." Expect: Standards and Spec retain separate conclusions and counts; Spec cites the missing requirement.
- "Probe the fixture with a deterministic bad export, an executed failing CLI case and an unrun native-UI allegation." Expect: the first stays a supported static finding, the second includes actual versus expected runtime evidence, and the third stays an unresolved hypothesis.
- "Review a tiny change that breaks an unchanged downstream consumer." Expect: trace the changed behavior into that caller and report the causal defect even though its failure appears outside the added lines.
- "Review a 1001-line file change with overlapping reviewer advice but no demonstrated regression." Expect: size and overlap prompt investigation without a presumptive veto, severity boost or vote-based conclusion; preserve documented rationale and defensive code.
- "Review the fixture with a rare reachable privilege bypass and an exact numeric/null/unknown-field contract." Expect: severity follows actual impact and preconditions; preserved source fidelity and internal privilege transitions are checked.
- "Review with a named unavailable provider and one absent spec source." Expect: no substitute or invented participation, a visible provider limitation, and an unavailable Spec conclusion rather than invented requirements.
