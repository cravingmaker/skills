# Work decomposition examples

Run each prompt with and without this skill in fresh, separately restored fixtures; keep tools, model settings, dependencies, and communication rules constant. Verify the candidate is available only in the treatment through every enabled discovery source; an unproven baseline is invalid. Record prompt, input and skill revisions, inventories, host/model versions, traces, artifacts, expected versus observed behavior, and coordination cost before marking this skill evaluated. Charge each model-powered arm against the same fleet budget and concurrency pool.

## Activation

- "Decide whether agents would help this migration, then give the useful workers ownership and a budget." Expect: a reasoned direct/delegated choice and a checked graph before dispatch.
- "Split two consumers of this fixed API contract across agents and reserve room to integrate them." Expect: disjoint writes, an explicit integration owner, dependencies, and a finite allowance.

- An approved local ticket graph and a spec at configured nondefault paths are imported without rewording or another breakdown.

## Near miss

- "Rename this function in one file." Expect: direct execution without a team or run scaffold.
- "Explain what a dependency graph is." Expect: an explanation without launching workers.
- "You are the assigned writer; edit only this skill and do not delegate." Expect: the bounded leaf assignment.

- Write tickets from this spec. Expect the `to-tickets` skill, with no ownership plan or dispatch.

## Outcome

- **Direct choice.** For a cohesive fix with "use agents if helpful", no child starts and the reason is the shared context and lack of an independent task.
- **Ownership.** Two unordered writers claiming a directory and a child file fail check-plan.py; a real dependency or disjoint drafts passes, including when the conflicting tasks name the same owner.
- **Ceiling.** With eight active runs across providers, descendants, and eval arms, a ninth is queued; a lower host limit wins; the recorded ninth-active plan also fails the checker.
- **Finite run.** Repeated new findings and replacement workers consume the original allowance even at concurrency one; exhaustion leaves the unmet condition explicit rather than resetting totals or approving it.
- **Reserve and accounting.** A child cannot delegate without an explicit shared allocation; idempotent retrieval of one receipt is counted once; a timed-out dispatch retains its slot until reconciliation; integration and verification retain capacity.
- Missing, empty, or placeholder Proof rejects a ticket before stdout JSON; exact status, Proof, hashes and blocker order survive import. Unknown, duplicate, partially consumed or ambiguous blockers and cycles fail; fixing them passes repeat runs without writes. A raw skeleton fails until all coordinator placeholders are resolved. Unknown-first probes, verifiable boundaries, separate ownership and host-owned isolation reuse one record and budget.
