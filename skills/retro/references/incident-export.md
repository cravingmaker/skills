# Optional incident follow-ups

Read this only when the user requests an export, issue draft, or similar-session comparison. Use the current authority for the requested action; a retrospective alone authorizes no public issue, message, archive, or wider history sweep.

## A requested issue

Use sufficient connected search before a supported CLI or API fallback. Search open and closed issues in the relevant project for the actual symptom before preparing another report. Record the queries, closest matches, and any access limit; do not substitute a fixed upstream repository. Use the project's issue template or the main skill's issue asset when none applies. Keep expected and observed behavior, reproduction, environment provenance, evidence, and unknown causal attribution distinct. Preserve a supplied human quotation faithfully after marked redaction. Attribution follows the user and repository, rather than mandatory model branding. Posting, replying, and attaching use their explicit existing task authority; a requested local draft remains local. If posted, return the exact issue or comment link and state which attachments actually exist.

## A requested bundle

Use the narrowest export scope that answers the request: skeleton, cited evidence, or the explicitly requested fuller record. Skeleton omits result bodies, cited evidence includes the commands and results needed for findings, and fuller export retains additional authorized content. Explain limits if the chosen level removes a finding's support. Create a private task-owned export directory and apply the main skill's redaction reference to its copies.

Keep case, report, environment provenance, findings, timeline, source excerpts, and README consistent. Condensed excerpts retain original source line/message markers and relationships; never imply they are the complete raw history. Keep exact historical anchors mapped to the exported evidence. Record privacy review and evidence support separately, with omissions and unresolved checks. When an archive is requested and authorized, archive the reviewed files, verify its file set and contents, and report its actual location. Record delivery separately so creating an archive does not silently change the already reviewed files.

## Requested similar sessions

Derive a signature from confirmed findings: a supported error string, repeated command, skill sequence, or behavior following an established event. Search only the authorized project and period with supported search or configured local records. Measure and narrow candidate files, confirm identities, and inspect only relevant regions. For each marker return hit, searched miss, or unknown with exact evidence; retain rejected plausible candidates where needed. Several similar symptoms do not by themselves establish a shared cause.
