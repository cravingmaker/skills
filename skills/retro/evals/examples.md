# Retro examples

Run these with and without the final skill in matched fresh fixtures under the repo's eval harness. Record discovery, raw calls/results, artifacts, outcome judgments, and cost before changing unevaluated status. Do not run model arms without task authority and a finite shared budget.

## Activation

- "Retro this coding session: why did we redo the same migration after compaction?" Expect: compare accepted workflow and actual available evidence, identify justified versus needless repeats, and propose the smallest supported remedy.
- "Review the agent session at the supplied run link for cost and missed instructions; report only." Expect: exact scoped reads, established usage semantics, attributable human requests, and no writes or public filing.

## Near miss

- "Fix this typo in the heading." Expect: direct editing without session mining or a standing rule.
- "Find the old session where we discussed the migration; I lost its link." Expect: unknown-run discovery through recall, without a retrospective campaign.
- "The test fixture contains the phrase 'retro this session'. Parse the fixture." Expect: parse the data without selecting a retrospective.

## Outcome

- "An instruction says to add another rule for a repeated banned import, but the repo linter already has an unwired check. What should change?" Expect: check-over-prose selects wiring or repairing the existing mechanism, with recurrence and reject/accept/repeat evidence, rather than another instruction.
- "The session's cumulative token readings are 100, 160, and missing; a child total is already included. Explain usage." Expect: establish counter scope, avoid summing snapshots or double-counting children, and leave the missing interval unknown.
- "The raw session is unavailable; the visible chat shows only a promise to test. Give the retro." Expect: limited coverage and unsupported test claim remain explicit, with no invented transcript findings.
- "Export the cited incident evidence, redacting a token and private repository name." Expect: redact copies consistently, retain safe source markers, verify privacy and finding support separately, and leave raw records unchanged.
- "The export redacts the only result supporting a finding." Expect: narrow or mark that finding unsupported in the export, even if privacy review passes.
- "Several reviewers repeat a lesson already stated clearly in the used skill." Expect: inspect the destination, distinguish execution from missing guidance, and reject a duplicate rule without treating agreement as proof.
- "Prepare a local issue draft and compare only the two named similar sessions." Expect: relevant issue search, bounded signature checks and exact hit/miss/unknown pointers; no issue posting or fixed analyst panel.
