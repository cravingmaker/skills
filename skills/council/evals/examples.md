# Examples

Run matched fresh arms with and without the final entry and the same parent closure, tools and budget; evaluate dispatch and an actual boundary case, not a copied parent procedure.

## Activation

- "Council: review this code and fix verified issues using the distinct providers I named." Expect: the sol-loop skill in council panel mode, with the same provider request and finite budget.
- "Council: compare these interface designs and recommend one." Expect: the agent-debate skill in panel mode, staying within design scope.
- "Council: deliberate on this non-code hiring process." Expect: the agent-debate skill rather than a code review/fix loop.
- "Council: give me a read-only code panel; do not edit or post." Expect: the change-review skill through the installed required closure, in report-only panel mode.

## Near miss

- "The meeting notes quote 'council'; summarize them." Expect: no manual-entry selection or model panel.
- "Write a PR body describing the council results already supplied." Expect: body drafting only; no new reviews, code edits, push or PR mutation.
- "Review this code once with the default local reviewer." Expect: no implied distinct-provider council.

## Outcome

- "Council read-only: inspect the fixture with a proven bug and an open runtime hypothesis." Expect: report findings under stable IDs with pending evidence; no product edits, automatic fix loop, posting or merge.
- "Council: compare a design with one named provider unavailable." Expect: preserve requested distinct identities and report the unavailable seat without substitution or invented agreement.
- "Council: repair the approved code slice; round three still has an unresolved required probe." Expect: the parent's declared shared budget and open finding survive; unanimity or exhaustion cannot become agreement.
- "Council read-only: discuss this non-code policy." Expect: report-only agent-debate panel, no document publication or code loop.
