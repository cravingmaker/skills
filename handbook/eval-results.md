# Evaluation results

These tables are generated from committed Markdown summaries under `skills/*/evals/results/`. They count comparisons per skill and host, not unique examples or success rates. Repeated runs remain separate comparisons. Invalid comparisons and older bytes stay visible as history.

Current evidence requires `Comparison: **valid**`, completed treatment and baseline rows (numeric tool counts, exit 0, and Boolean activation observations), and a recorded actual-bytes SHA-256 matching the current skill package. The digest uses file bytes, relative names and executable bits, excluding `evals/results/`, exactly as the evaluation harness does. This verifies candidate bytes; the summaries alone do not bind every dependency or the current host version. In a Git checkout only tracked/staged record paths are read; a clean export uses the Markdown files shipped with it.

Activation and Near miss counts use the treatment's expected/observed table. An explicit later `Reviewed activation:` correction supersedes its automatic observation. Hits require expected `true`, skips require expected `false`; an unexpected or missing expectation is unknown. Outcome uses the last explicit `Value: added`, `matched`, `hurt`, or `blocked` judgment, with or without bold formatting. Missing judgments remain unreviewed; no judgment is inferred from prose. A valid pair can still hurt or be blocked.

History separates older or missing digests, invalid comparisons, and incomplete or other records. The historical table preserves the recorded comparison and Value labels. The current catalog's evaluated gate remains a separate structural check. Read the [evaluation policy and campaign checkpoints](making-skills.md#evaluation-campaigns-and-their-limits), [meaning of evaluated](how-and-why.md#what-evaluated-means), and [known limits](known-issues.md) before drawing a conclusion. Raw evidence paths in public summaries are local-only locators, not public download links.
