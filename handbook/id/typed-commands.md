# Perintah yang diketik

Entri manual membutuhkan pemilihan sengaja: `/<name>` di Claude Code, `$<name>` di Codex. Kebijakan host menekan pemilihan implisit; kebijakan itu tidak mencegah pembacaan filesystem atau komposisi wajib. Setiap entri di bawah menjelaskan alasan praktis memilih alurnya secara eksplisit; katalog mencatat preferensi, bukan alasan historis.

Mengetik perintah memilih skill dan mode. Perintah tidak pernah memberi kewenangan tambahan: perintah untuk membuat draf tetap hanya membuat draf sampai Anda meminta pengajuan, push, atau merge.

## Cara mengetik pada setiap host

| Host | Sintaks | Contoh |
| --- | --- | --- |
| Claude Code | Awali dengan slash, lalu permintaan Anda pada baris yang sama. | `/grill-me split the billing service into two deployables` |
| Codex | Awali dengan tanda dolar, lalu permintaan Anda. | `$grill-me split the billing service into two deployables` |
| T3 Code | Gunakan sintaks host yang menjalankan thread tersebut. | `/grill-me ...` dalam thread Claude, `$grill-me ...` dalam thread Codex. Belum diuji secara terpisah. |

Ketik perintah pada awal pesan. Evaluasi Claude Code mengetik `/<name>` di awal; kebanyakan evaluasi Codex mengetik `$<name>` di awal.

Menyebut nama dalam kalimat tidak sama. Pada evaluasi Codex PR #5, prompt yang hanya menyebut skill manual dengan kata-kata tidak selalu memuatnya, sehingga kasus tersisa beralih ke `$<name>`. Pada evaluasi Codex PR #7, frasa biasa "Full send this" tidak memuat `full-send` maupun `full-stop`.

Halaman ini mendokumentasikan pemanggilan native yang tercatat untuk entri manual. Pemilihan eksplisit entri lain bergantung pada perilaku host; catatan ini tidak membuktikan semua perintah semacam itu.

## Arti dan batas pemilihan manual

Katalog menandai skill ini `invocation: user`. Setiap host menegakkannya dengan cara berbeda:

| Host | Penegakan | Dampak |
| --- | --- | --- |
| Claude Code | `skillOverrides` ditetapkan ke `user-invocable-only` oleh adapter installer `--host claude`. | Skill tetap tercantum dan dapat diketik pengguna, tetapi tersembunyi dari daftar skill model sendiri. |
| Codex | `agents/openai.yaml` dengan `policy.allow_implicit_invocation: false`, dihasilkan dalam folder skill. | Codex tidak memilih skill secara implisit; `$<name>` tetap memilihnya. |

Tiga batas pemilihan manual:

- **Skill lain tetap dapat membacanya.** Skill yang membutuhkan skill manual tetap membacanya berdasarkan nama. `implement-spec` membaca `implement`, `full-stop` membaca `full-send`, dan `agent-orchestrator` membaca `to-spec`, `to-tickets`, `grill-with-docs`, `implement-spec`, dan `retro`.
- **Berkasnya tidak terkunci.** Model yang sudah mengetahui path dapat membaca `SKILL.md` dari disk. Evaluasi melihat ini sekali pada setiap host: `to-questionnaire` di Claude Code, yang tidak terulang pada pengulangan baru, dan `teach` di Codex, yang diperbaiki dengan mempersempit deskripsi. Lihat [masalah yang diketahui](known-issues.md#manual-only-bukan-batas-akses-berkas).
- **Tidak ada kewenangan tambahan.** `/pr` membuat draf secara default dan mengajukan jika permintaan yang sama atau kewenangan tugas yang sudah ada mengizinkan. `/full-stop` tidak pernah melakukan merge. Permintaan merge eksplisit memberi kewenangan merge; metode `full-send` memiliki prosedur yang dijaga. Memuat perintah tidak memberi kewenangan di luar permintaan.

Katalog mencatat skill yang harus diketik, bukan alasannya. Alasan pada setiap bagian di bawah mengikuti fungsi skill tersebut.

Tujuh entri bersifat tipis: membuka skill lain dalam satu mode tanpa menambah metode sendiri. Entri itu adalah `/grill-me`, `/bro`, `/wait-what`, `/pr`, `/full-stop`, `/council`, dan `/interrogate`. Jika skill induknya tidak terpasang, entri menyatakannya lalu berhenti alih-alih mengarang; evaluasi Claude Code mencatat ini untuk `/bro`, `/pr`, dan `/full-stop`.

## Pembentukan dan perencanaan

### `/grill-with-docs`

- **Saat diketik:** memulai wawancara tentang rencana Anda, sambil memperbarui glosarium dan catatan keputusan saat jawaban disepakati.
- **Membuka:** wawancara `grilling` dengan disiplin `domain-modeling` aktif.
- **Membutuhkan:** `docs/agents/domain.md` dari `/setup-agent-skills`. Tanpanya, skill menyatakan kekurangan itu dan menawarkan wawancara biasa tanpa penulisan dokumen.
- **Perubahan:** menulis setiap istilah yang disepakati ke glosarium yang dikonfigurasi, serta ADR hanya jika keputusan sulit dibatalkan, mengejutkan tanpa konteks, memiliki trade-off nyata, dan Anda menerimanya. Commit, kode, dan penulisan tracker membutuhkan permintaan tersendiri.
- **Penutup:** keputusan yang disepakati, hal tertunda, setiap perubahan glosarium dan ADR beserta path, serta `/to-spec` sebagai langkah berikutnya jika hasilnya perlu dibangun. Skill dapat menjalankan satu "builder check" opsional, yaitu pembaca baru atas penutup, yang dihitung dalam anggaran proses.
- **Alasan manual:** skill menulis dokumen proyek. Wawancara biasa yang tidak menulis apa pun adalah default otomatis.
- **Contoh:** `/grill-with-docs we want partial refunds on orders`

### `/grill-me`

- **Saat diketik:** memulai wawancara yang sama dalam mode tanpa dokumen.
- **Membuka:** skill `grilling`, mode tanpa dokumen.
- **Perubahan:** tidak ada. Hasil tetap dalam percakapan. Jika Anda meminta pencatatan istilah, skill menyebut `/grill-with-docs` dan hanya beralih atas perintah Anda.
- **Cara wawancara berjalan:** putaran bernomor; setiap pertanyaan memiliki jawaban yang disarankan, dengan "yes" berarti menerimanya. Fakta dicari, bukan ditanyakan. Pilihan yang sudah disepakati dicantumkan, bukan ditanyakan ulang. Wawancara berhenti saat jawaban tersisa tidak akan mengubah rencana, lalu menunggu konfirmasi penutup dari Anda.
- **Alasan manual:** "grill me" dapat muncul dalam catatan dan log. Permintaan biasa ("grill me on this plan") sudah mengarah ke skill otomatis `grilling`, sehingga bentuk manual adalah pintasan, bukan metode baru.
- **Contoh:** `/grill-me split the billing service into two deployables`

### `/to-spec`

- **Saat diketik:** menulis rencana yang disepakati sebagai spec engineering. Skill tidak mewawancarai Anda.
- **Membuka:** skill lengkap; menggunakan `domain-modeling` untuk istilah glosarium.
- **Keluaran:** user story bernomor, masing-masing dengan **Acceptance** dan **Proof** (permukaan nyata yang dijalankan dan hasil yang diamati), usulan test seam, pertanyaan terbuka beserta pengambil keputusan, dan daftar Sources dengan SHA-256 setiap berkas.
- **Perubahan:** mengajukan spec ke lokasi yang ditetapkan `docs/agents/issue-tracker.md`, jika pengajuan termasuk dalam permintaan. Tanpa setup tracker atau dengan permintaan draft-only, skill mengembalikan draf dalam percakapan.
- **Alasan manual:** Anda menentukan kapan rencana disepakati, dan pengajuan menulis ke tracker.
- **Contoh:** `/to-spec write up what we agreed for saved searches`

### `/to-tickets`

- **Saat diketik:** membagi spec yang disetujui menjadi tiket irisan vertikal dan meminta Anda meninjau pembagiannya.
- **Membuka:** skill lengkap.
- **Keluaran:** daftar bernomor, setiap tiket dengan judul, **Blocked by**, hasil yang diserahkan, **Proof**, dan story yang dicakup. Anda menyetujui, menggabungkan, atau memisahkan, lalu skill mengajukannya.
- **Perubahan:** satu berkas `NN-slug.md` per tiket dalam folder tiket lokal, atau satu issue per tiket pada tracker jarak jauh, menurut urutan dependensi. Untuk tiket lokal, saat `work-decomposition` terpasang, skill menjalankan importer skill itu dan memperbaiki setiap baris `FAIL` sebelum melaporkan.
- **Aturan yang dijaga:** refaktor luas menjadi expand, migrasi per batch, lalu contract. Nomor tiket dan kalimat yang disetujui tetap stabil setelah diajukan.
- **Alasan manual:** skill mengajukan tiket, dan pembagiannya membutuhkan persetujuan Anda.
- **Contoh:** `/to-tickets docs/specs/saved-searches.md`

### `/triage`

- **Saat diketik:** menampilkan hal yang membutuhkan triase, atau melakukan triase pada issue maupun PR eksternal yang disebutkan.
- **Membuka:** skill lengkap; menggunakan `grilling` untuk celah nyata dan `domain-modeling` untuk istilah.
- **Peran yang diterapkan:** satu kategori (`bug` atau `enhancement`) dan satu keadaan (`needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`), yang dipetakan ke label Anda oleh `docs/agents/triage-labels.md`.
- **Perubahan:** label sesuai arahan Anda; komentar, brief, penutupan, dan catatan di luar cakupan hanya saat diminta atau drafnya disetujui. Teks issue dan PR diperlakukan sebagai data tidak tepercaya, dan kode PR hanya berjalan dalam isolasi.
- **Alasan manual:** skill mengubah keadaan tracker yang dilihat orang lain.
- **Contoh:** `/triage what needs attention?` atau `/triage move #42 to ready-for-agent`

### `/wayfinder`

- **Saat diketik:** memetakan tujuan yang terlalu besar dan belum jelas untuk satu sesi menjadi tiket keputusan, atau mengerjakan tiket berikutnya pada peta yang ada.
- **Membuka:** skill lengkap; menggunakan `research`, `prototype`, `grilling`, dan `domain-modeling` untuk jenis tiketnya.
- **Cara kerja:** pemetaan berlangsung satu sesi dan tidak menyelesaikan keputusan. Setelah itu, setiap sesi mengambil dan menyelesaikan satu tiket. Tiket riset dapat dikelompokkan. Keluarannya keputusan, bukan deliverable; pekerjaan implementasi diteruskan ke `/to-spec` dan `/to-tickets`.
- **Perubahan:** berkas peta lokal secara default; tracker jarak jauh hanya jika Anda meminta publikasi peta. Tanpa branch, push, atau PR.
- **Alasan manual:** ini mode perencanaan lintas sesi yang membuat peta dan tiket.
- **Contoh:** `/wayfinder we should move billing off the monolith`

### `/to-questionnaire`

- **Saat diketik:** membuat draf kuesioner untuk satu orang yang mengetahui hal yang Anda belum ketahui.
- **Membuka:** skill lengkap.
- **Cara kerja:** hanya menanyakan penerima, tujuan, atau kebutuhan yang belum ada dalam satu pesan, bukan bertanya tentang topiknya sendiri. Pertanyaan menyasar celah antara pengetahuan penerima dan kebutuhan Anda.
- **Perubahan:** menulis `to-questionnaire-<slug>.md` dalam folder saat ini, atau path yang Anda sebutkan. Tidak pernah mengirim, mem-posting, atau menerbitkan.
- **Alasan manual:** skill membuat dokumen untuk orang lain. Satu evaluasi Claude Code melihat permintaan survei biasa membaca berkas skill ini dari disk; pengulangan baru tidak mengulanginya.
- **Contoh:** `/to-questionnaire ask the finance lead how refunds are reconciled today`

### `/setup-agent-skills`

- **Saat diketik:** membuat atau memperbarui kontrak proyek yang dibaca skill pembentukan rencana.
- **Membuka:** skill lengkap.
- **Perubahan:** satu blok `## Agent skills` dalam berkas instruksi proyek, ditambah `docs/agents/issue-tracker.md`, `docs/agents/domain.md`, dan, jika `triage` terpasang, `docs/agents/triage-labels.md`. Skill mempertahankan path dan label yang ada, membuat berkas glosarium serta ADR saat dibutuhkan, dan dapat diulang tanpa perubahan baru.
- **Tidak termasuk:** membuat label atau issue jarak jauh, settings global, hook, atau kebijakan pemanggilan host.
- **Alasan manual:** skill mengedit berkas instruksi proyek Anda.
- **Contoh:** `/setup-agent-skills use GitHub issues and a single glossary`

## Pemahaman dan penulisan

### `/sharpen`

- **Saat diketik:** menulis ulang prompt menjadi versi lebih mendalam dari tugas yang sama, tanpa mengerjakan tugasnya.
- **Membuka:** skill lengkap. Isinya adalah teks pstack upstream yang tidak diubah.
- **Keluaran:** hal yang akan ditambahkan profesional berpengalaman, bahan awal paling mentah, metode dan alat, serta bukti di luar percakapan yang menunjukkan hasil benar; lalu prompt yang ditulis ulang, dengan pilihan milik Anda tetap terbuka.
- **Alasan manual:** jika aktif sendiri, permintaan biasa akan dikembalikan sebagai prompt yang ditulis ulang, bukan hasil.
- **Contoh:** `/sharpen write a migration plan for the orders table`

### `/bro`

- **Saat diketik:** memperjelas jawaban terakhir agen dengan kata sederhana.
- **Membuka:** skill `clear-communication`, mode "Repair your own last message".
- **Mempertahankan:** setiap fakta, angka, batasan, dan ketidakpastian jawaban asli. Tidak memulai tugas baru.
- **Alasan manual:** "bro" adalah kata sehari-hari, dan penggunaannya dalam kutipan tidak boleh memilih apa pun.
- **Contoh:** `/bro`

### `/wait-what`

- **Saat diketik:** menjelaskan satu poin yang membingungkan dalam jawaban terakhir, menggunakan istilah proyek Anda.
- **Membuka:** skill `clear-communication`, mode perbaikan yang sama dengan tambahan konteks.
- **Mempertahankan:** batas bukti yang dinyatakan, seperti "static only" atau "not run in the UI". Tidak membuat kursus atau dokumen.
- **Alasan manual:** sama seperti `/bro`.
- **Contoh:** `/wait-what what does settlement mean here?`

### `/teach`

- **Saat diketik:** menjelaskan konsep atau subsistem secara bertahap: definisi sederhana dahulu, lalu mekanisme, alasan, contoh, dan edge case sedalam yang Anda minta.
- **Membuka:** skill lengkap; membutuhkan `clear-communication`, `how`, dan `why`.
- **Perubahan:** tidak ada secara default. Hanya jika Anda meminta menyimpan kursus, skill menulis ruang belajar (misi, sumber daya, pelajaran, kemajuan) pada path pilihan Anda.
- **Kuis:** hanya saat diminta.
- **Alasan manual:** penjelasan biasa sebaiknya tetap biasa. `how` dan `why`, yang otomatis, menjawab sebagian besar pertanyaan tanpa skill ini.
- **Contoh:** `/teach how does the export queue retry failed jobs?`

## Desain, implementasi, dan tinjauan

### `/improve-codebase-architecture`

- **Saat diketik:** menyurvei codebase, mulai dari berkas yang paling sering berubah, lalu mengusulkan refaktor untuk memperdalam modul.
- **Membuka:** skill lengkap; membutuhkan `codebase-design` sebagai kosakatanya.
- **Keluaran:** laporan HTML statis dan offline dalam folder sementara Anda, bukan repositori, dengan satu kartu per kandidat: berkas dan baris, masalah, solusi, manfaat, sebelum dan sesudah, bukti, dan kekuatannya. Lalu menanyakan kandidat yang ingin Anda telusuri.
- **Perubahan:** tidak mengubah kode produk sebelum Anda memilih kandidat dan memberi izin. Diagram memuat Mermaid dari CDN hanya jika Anda menerimanya.
- **Alasan manual:** survei seluruh codebase mahal, dan keluarannya laporan untuk ditinjau.
- **Contoh:** `/improve-codebase-architecture focus on the billing package`

### `/implement`

- **Saat diketik:** membangun satu tiket yang disetujui, irisan spec, atau perubahan yang disepakati, membuktikannya, lalu meninjaunya.
- **Membuka:** skill lengkap; membutuhkan `tdd` dan `change-review`.
- **Cara kerja:** membaca acceptance dan Proof; memutuskan pertentangan dengan spec sebagai acuan dan mencatat setiap keputusan; menggunakan test terlebih dahulu saat ada seam bermakna; menjalankan suite terkait; membersihkan diff sendiri; menilainya terhadap tiket.
- **Perubahan:** kode dalam irisan; commit hanya jika termasuk permintaan Anda. Push, PR, dan pembaruan tracker membutuhkan permintaan tersendiri.
- **Laporan:** COMPLETE, PARTIAL, atau BLOCKED di awal, lalu perintah Proof dan hasil yang diamati.
- **Alasan manual:** skill mengubah kode. Koordinator mengaksesnya melalui `/implement-spec`, yang meminta setiap pekerja membacanya.
- **Contoh:** `/implement ticket 03`

### `/implement-spec`

- **Saat diketik:** menjalankan seluruh graf tiket yang disetujui menjadi satu branch terintegrasi yang diverifikasi.
- **Membuka:** skill lengkap; membutuhkan `work-decomposition`, `agent-briefing`, `decision-log`, `result-verification`, dan `implement`.
- **Cara kerja:** mengimpor tiket secara persis, menetapkan anggaran terbatas sebelum start pertama, menyimpan catatan di disk (`PLAN.md`, `LOG.md`, `DECISIONS.md`), memberi brief satu pekerja per tiket siap, menerima hasil berdasarkan pengulangan Proof, meninjau dalam tiga putaran perbaikan secara default, menggabungkan ke branch integrasi, dan menjalankan semua pemeriksaan acceptance di sana.
- **Batas:** satu koordinator memiliki setiap start; paling banyak delapan subagen aktif sekaligus, atau lebih sedikit jika host atau Anda menetapkan batas lebih rendah. Jika host tidak dapat melakukan dispatch pekerja atau mengisolasi checkout, skill berhenti pada preflight berbasis sumber dan melaporkan pelaksanaan terhambat.
- **Alasan manual:** skill memulai banyak agen dan menghabiskan anggaran model.
- **Contoh:** `/implement-spec docs/specs/saved-searches.md`

### `/council`

- **Saat diketik:** meminta panel dari penyedia berbeda untuk satu pertanyaan.
- **Membuka:** tinjauan kode dengan perbaikan mengarah ke `sol-loop` mode panel; pertanyaan desain atau nonkode mengarah ke `agent-debate` mode panel. Permintaan read-only berlaku lebih dahulu: untuk kode, skill membuka `change-review` sebagai panel laporan saja.
- **Mempertahankan:** penyedia yang Anda sebutkan. Penyedia yang hilang dilaporkan tidak tersedia, tidak pernah diganti.
- **Alasan manual:** "council" adalah kata biasa, dan setiap kursi panel memerlukan satu start model.
- **Contoh:** `/council review this branch with Claude and Codex, report only`

### `/interrogate`

- **Saat diketik:** menjalankan tinjauan adversarial berupa laporan saja yang mencoba merusak perubahan dengan probe terarah.
- **Membuka:** skill `change-review` dalam mode panel probe tanpa siklus perbaikan.
- **Aturan bukti:** klaim runtime membutuhkan probe yang dijalankan; klaim statis tetap menyertakan bukti statis; klaim runtime yang belum dijalankan tetap menjadi hipotesis terbuka di bawah ID temuannya. Setiap percobaan probe, termasuk kegagalan dan pengulangan, dihitung dalam jatah yang dinyatakan.
- **Alasan manual:** probe menjalankan perintah terhadap kode Anda, dan ini mode eksplisit.
- **Contoh:** `/interrogate try to break the new export path`

### `/maintain-verification-skill`

- **Saat diketik:** mengaudit driver proyek yang ada (skill yang menjalankan dan mengendalikan aplikasi nyata) terhadap sumber serta perilaku sebenarnya.
- **Membuka:** skill lengkap. Tidak membutuhkan `create-verification-skill`.
- **Keluaran:** **clean**, **changed**, atau **blocked**, dengan setiap temuan dikelompokkan sebagai recipe drift, celah harness, hambatan lingkungan, atau regresi produk.
- **Perubahan:** hanya berkas driver sendiri, dan hanya jika edit diizinkan. Regresi produk dilaporkan, tidak diperbaiki di sini.
- **Alasan manual:** audit lengkap menjalankan aplikasi nyata pada setiap fitur yang dinyatakan.
- **Contoh:** `/maintain-verification-skill verify-notes-web`

## Pengiriman

### `/pr`

- **Saat diketik:** menulis judul dan isi PR untuk perubahan saat ini sebagai draf lokal.
- **Membuka:** skill `file-pr`, mode body-only.
- **Perubahan:** tidak ada perubahan jarak jauh. Minta pengajuan atau pembaruan dalam pesan yang sama ("`/pr` and open it as a draft"), atau pertahankan kewenangan pengajuan yang sudah ada; skill lalu menggunakan mode file dari file-pr.
- **Bentuk isi:** ditentukan template repositori dan PR terbaru yang di-merge. Jika tidak ada: Why, What changed, Scope, Evidence, Risk, Tradeoffs.
- **Alasan manual:** "pr" muncul dalam hampir setiap percakapan pemrograman.
- **Contoh:** `/pr`

### `/full-send`

- **Saat diketik:** menyerahkan seluruh proses pengiriman kepada agen sampai PR di-merge.
- **Membuka:** skill lengkap; membutuhkan `file-pr`, `babysit-pr`, `sol-loop`, dan `result-verification`.
- **Izin yang diberikan:** merge setelah pemeriksaan wajib lulus, force-push branch milik tugas dengan lease yang dicatat setelah rebase, dan test yang dibutuhkan Proof tanpa bertanya dahulu. Tidak memberi izin perubahan produksi, penghapusan data, penutupan PR, atau force-push branch lain.
- **Syarat merge:** Proof mencakup diff; pemeriksaan, bot, dan persetujuan wajib menurut kebijakan repositori tersedia; setiap thread tinjauan, berapa pun usianya, ditangani; tidak ada tinjauan manusia yang meminta perubahan; branch mutakhir dan dapat di-merge; pekerjaan tetap dalam tiga putaran tinjauan secara default. Merge menggunakan penjagaan head, lalu hasilnya dibaca kembali.
- **Alasan manual:** skill memilih cakupan penyerahan penuh; permintaan merge eksplisit juga dapat mengizinkan cakupan itu.
- **Contoh:** `/full-send fix the off-by-one in the pager and get it merged`

### `/full-stop`

- **Saat diketik:** melakukan semua yang dilakukan `/full-send` kecuali merge, dan meninggalkan PR terbuka serta siap.
- **Membuka:** skill `full-send`, mode prepare-only.
- **Mempertahankan:** no-merge pada setiap helper dan anak. Skill membatalkan entri auto-merge atau merge-queue milik proses dan membaca kembali untuk memastikan tidak ada yang tersisa.
- **Penutup:** siap merge, menunggu persetujuan wajib, atau terhambat, beserta tautan PR dan head final.
- **Alasan manual:** "full stop" adalah tanda baca dan ungkapan penegasan biasa.
- **Contoh:** `/full-stop get this ready for review`

## Kelanjutan

### `/retro`

- **Saat diketik:** membandingkan tindakan sesi ini dengan permintaan Anda dan mencari perbaikan terkecil yang didukung bukti.
- **Membuka:** skill lengkap; membutuhkan `writing-for-agents`.
- **Aturan bukti:** saat Anda menyebut sumber proyek dan riwayat yang diizinkan, skill membaca hanya path tersebut, tanpa daftar direktori atau status/pencarian luas; riwayat Git adalah sumber terpisah yang digunakan hanya saat disebutkan. Referensi metode terpasang tetap merupakan input metode. Riwayat yang hilang tetap tidak diketahui.
- **Mengutamakan:** pemeriksaan, tipe, lint, atau test terhubung dibanding aturan tertulis baru; kesalahan berulang diarahkan ke skill `correct`.
- **Perubahan:** edit hanya dalam permintaan Anda; selain itu berupa usulan. Tanpa issue publik atau settings global.
- **Alasan manual:** retrospektif berjalan hanya atas permintaan; menyelesaikan pekerjaan tidak otomatis memulainya.
- **Contoh:** `/retro why did the last run reread the spec three times?`

### `/handoff`

- **Saat diketik:** menulis catatan kelanjutan agar sesi baru dapat melanjutkan dari keadaan yang persis.
- **Membuka:** skill lengkap.
- **Perubahan:** satu catatan dalam folder sementara sistem operasi, di luar workspace, dengan izin terbatas. Catatan menautkan catatan proses, spec, branch, dan PR alih-alih menyalinnya, serta mencantumkan skill yang disarankan.
- **Mempertahankan:** anggaran yang sudah digunakan, pekerja aktif, pilihan terbuka, dan tindakan siap berikutnya. Rahasia disamarkan.
- **Alasan manual:** Anda menentukan kapan sesi berakhir. Folder sementara dapat dibersihkan; catatan jangka panjang menjadi tanggung jawab `decision-log`.
- **Contoh:** `/handoff next session should finish the import tests`

### `/ketchup`

- **Saat diketik:** memberi kabar semua perkembangan sejak pesan terakhir Anda: perubahan, keadaan nyata PR, CI, dan agen, serta setiap pilihan yang masih menunggu Anda.
- **Membuka:** skill lengkap; membutuhkan `clear-communication`.
- **Perubahan:** tidak ada. Skill tidak menjalankan ulang CI, memulai watcher, mem-posting, atau melakukan merge.
- **Rentang lebih luas:** minta periode tertentu ("`/ketchup` for last week") dan skill menentukan tanggal konkret serta memeriksa keadaan langsung sebelum menyatakan sesuatu sudah dikirim.
- **Alasan manual:** namanya permainan kata dari "catch up"; skill berjalan hanya atas permintaan.
- **Contoh:** `/ketchup`
